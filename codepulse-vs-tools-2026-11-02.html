Bottom line. The other tools overlap with CodePulse on generic Python problems, but they miss most of what is specific to AI back ends. They also bury what they do catch in much more noise.

  • Overlap. 93 of the 217 real issues (43%) are also flagged by at least one of Ruff, Bandit, Semgrep or SonarQube.
    • Most of that overlap comes from broad rules: Ruff's "blind except" (BLE001), and Ruff/Bandit's rule against SQL built from strings.
    • Blocking calls in async code are the one area where other tools match CodePulse issue for issue: Ruff's async rules and SonarQube's (S7493 file, S7487 subprocess, S7499 HTTP) each catch all or almost all 24.
  • CodePulse only. 124 issues (57%) were flagged by none of the other tools:
    • all 33 LLM-call issues: timeouts, output limits, failure handling, prompt assembly, history
    • all 23 unauthenticated endpoints
    • 21 of 24 cases of secrets or personal data written to logs
    • every thread, future and database-pool limit
    Of the 76 security and privacy issues, the other tools found 22.
  • P1s. 14 of the 17 P1 issues are also flagged by some tool, mostly by Bandit/Ruff's string-SQL and hard-coded-password rules. Three confirmed SQL injections were flagged by none of them: R2R chunks.py, and Open WebUI's MariaDB and Oracle vector stores.
  • No AI rules. SonarQube Community has no rules for LLM calls, prompts or agents. Its built-in "Sonar agentic AI" profile is a subset of its general rules, aimed at code written by AI, not at AI applications.
  • The other direction. A judged sample of 56 findings that the other tools raise and CodePulse does not gave:
    • 2 real issues, both from SonarQube: an unreferenced asyncio task that can lose a storage write, and a raise of a tuple instead of an exception. Both are now CodePulse checks (E07.unreferenced-task, E12.raise-non-exception, rules 2026.11.12). They catch both cases, plus 4 more broken raise statements in bisheng and DB-GPT that SonarQube had not listed.
    • 20 real but minor issues.
    • 34 false alarms. The main causes were MD5 used as an ID, list-form subprocess calls and config key names.

Which issues each tool also finds

An issue counts as found when the tool reports a rule from the same problem family within 3 lines (for example Bandit B608 or SonarQube S2077 for SQL built from strings). Broad rules count: Ruff BLE001 flags every except Exception, so it "finds" most error-handling issues without telling them apart from correct handlers.

Method and limits

  • Same inputs. The 171 files that hold the stored issues, at the pinned commits of the benchmark checkouts. Ruff 0.15.7 with every rule (--isolated --select ALL), Bandit 1.9.4, Semgrep 1.179.0 with the public p/python, p/owasp-top-ten and p/secrets packs (--metrics=off; rules downloaded, no code uploaded), SonarQube Community Build 26.10 running locally in Docker on 127.0.0.1.
  • Bias. The issue list came from CodePulse, so recall is measured on CodePulse's ground. The reverse section corrects for that with a judged sample of what the other tools see alone.
  • What was not measured. Commercial tiers: SonarQube Developer and Enterprise (taint analysis for injection), Semgrep Pro (cross-file data flow), CodeQL, Snyk Code. Taint tools would likely catch more of the SQL injections. LLM-specific checks were not found in the open rule sets used here.
  • Labels. Claude judges with the written rubric (bench/JUDGING.md); careful silver labels, not a human panel.
