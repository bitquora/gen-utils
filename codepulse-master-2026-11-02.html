Bottom line. CodePulse finds real problems in real, popular code, and after today's work it raises fewer false alarms everywhere it was measured without losing what it caught.

  • 82 public repositories reviewed:
    • 20 used to tune the rules
    • 15 held out and never used for tuning
    • 10 famous web apps
    • 22 LangGraph apps
    • 15 apps on other agent frameworks
    Also 66 deliberately vulnerable apps (RealVuln) and 255 fix commits.
  • Agent frameworks (spec 013, 2026-11-02).
    • The graph checks now see methods, imported functions and object methods as LangGraph nodes. Coverage of graph nodes went from 42% to 57%, which is nearly every node that has a function body.
    • 13 of the 18 newly flagged oversized nodes are real.
    • Two checks lost their false alarms: "state lifecycle" (10 of 10 were wrong on MessagesState, now 0) and "multi-writer", which now needs parallel branches (13 to 1).
    • CrewAI, LlamaIndex, PydanticAI, OpenAI Agents, Google ADK and AutoGen steps get the same node-size and logging checks.
    • Two new experimental checks: agent loops with no stop, and agent output parsed by hand.
  • 217 real issues stored, with 17 at P1. The strongest:
    • SQL injections in Langchain-Chatchat and R2R (two)
    • a SOQL injection in agno, steerable by prompt injection
    • a column-name injection in Superset
    • reset and session tokens written to logs in cognee, R2R and Label Studio
    • hardcoded signing and encryption keys
    • event-loop freezes and silent data loss
    • LangGraph apps: unauthenticated endpoints that wipe checkpoints or agent memory, or run any MCP tool
    • API keys and document text written to logs
    Five of these I traced to the input myself; the rest are carefully judged but unconfirmed. Nothing has been reported to any project.
  • Compared with other tools. On the same files, Ruff, Bandit, Semgrep and SonarQube together also flag 93 of the 217 real issues (43%), mostly through broad rules. None of them flag any LLM-call, endpoint-auth or concurrency-limit issue. A judged reverse sample found 2 real issues they catch that CodePulse missed; both are now CodePulse checks.
  • Correct share of findings, by volume, before → after today:
    • 20 tuning repos: 72% → 82%, with 187 of 189 real issues still reported
    • 15 held-out repos: 65% → 74%
    • 10 web apps: 84% → 91%
    • RealVuln: no detection lost, and unlabelled noise down 37%
  • Still true: most findings are correct but low-value hygiene (noqa reasons, error handling, test quality). Only about 1 in 5 (1 in 10 on the held-out set) is something you would ask a developer to fix. That is why the default severity now drops anything in tests, examples and scripts to low.

Detailed reports (same folder)

  • 20 large AI repositories: repo-by-repo cards, the full judged lists, the check scorecard (rules before today's changes).
  • 15 held-out AI repositories: the same layout, with today's rules and the blind check of removed findings.
  • 10 famous mixed web apps: the same layout, with today's rules.
  • CodePulse compared with Ruff, Bandit, Semgrep and SonarQube: which of the real issues each tool also finds, noise on the same files, and what they find that CodePulse misses.
  • 22 LangGraph applications: the graph checks judged in full, node mapping before and after spec 013.
  • 15 apps on other agent frameworks: CrewAI, LlamaIndex, PydanticAI, OpenAI Agents SDK, Google ADK, AutoGen.
  • RealVuln, fix commits and local-model judge (the first report).

Method and limits

  • Labels. Findings were judged by Claude reviewers with written rubrics (bench/JUDGING.md, bench/CLASSIFY.md), reading the full checkout; I traced the security findings called out here myself. These are careful silver labels, not a human expert panel.
  • Sampling. About 40–50 findings per repo, every check that fired at least 3 times, fixed seeds; rates are re-weighted by each check's real volume.
  • Held-out. The 15 held-out repos were picked by the same rule and never used to tune; their packets mixed in findings the new rules dropped, unlabelled, so judges could not favour either build.
  • Privacy. Public code only, read locally; nothing uploaded, posted or reported. The GitHub token was used read-only, sent only to api.github.com.
